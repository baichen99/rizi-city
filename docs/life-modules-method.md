# 日常生活导航样板 v1

本实现对应方案 #41 的北京、上海、广州试点。每城包含水、电、气、暖、气候和医保六张卡，共18张。**这是带来源及缺口的官方导航，不是已完成的账单、气候数据库或医保待遇库。** 上海和广州的取暖规则明确标为尚未覆盖；未覆盖不意味着免费、没有相关服务或不需要取暖。

## 数据与构建约定

- `data/life/{utilities,climate,healthcare}/*.json` 保存项目自写说明及链接，原文、截图、附件、价格表均未复制入库。
- `build_modules(city_ids)` 返回 `{city_id: [card, ...]}`，由主构建写入 `c.life.modules`。未知/非试点城市返回空列表，不复制邻城规则。
- 卡片保留 `coverage`、`reference_period`、`source_date`、`effective_from/to`、`verified_at`、`next_review_at`、证据定位和许可状态。未知来源发布日期、生效日或到期日保留 null，不能推断为永久有效。
- `verified_at` 是2026-11-09打开并阅读官方文本的日期，仅证明导航内容核验，不证明服务可用或政策现行性全部通过。列表页核验不等于链接内全部政策核验。
- `validate_modules()` 返回错误字符串列表；构建遇到结构错误、非政府链接、价格载荷或启用计算器请求会失败，不静默放行。
- 目前所有卡均 `usable=false`、`calculator_enabled=false`，源码中的 `link_only` 状态可显示为「官方导航／仅链接」，`missing` 为「尚未覆盖」，`pending_review` 为「待复核」，`expired` 为「已到期」。不可用绿色“现行规则已核实”标记替代。
- 超过复核日期或核验日在构建日之后，构建自动标记待复核；已知失效立即标记到期。原链接可保留作为历史入口，不能输出金额。独立复核未完成与资料可信度分开记录。

## 许可与维护

所有来源数据的再分发许可尚未核准，`redistribution_status=link_only`。仓库许可不自动授予来源全文/表格/数据集的再分发权。本轮发布的是链接、页面识别信息、事实范围和项目原创的导航说明；未批量下载、缓存或转发原文。将来若发布数字或曲线，须独立检查许可、单位、观测期/基准期、供应范围、当前效力和二次复核，不得只改一个状态位启用。

水电气暖和医保拟定下次复核日2027-02-09；气候背景拟定2027-11-09。这是显式复核窗口，不代表已创建自动任务，也不代表有专人承诺维护。维护责任人和独立复核人仍待仓库维护者指定，首次公式/医保及新来源应100%复核。价格变化、正式替代文件、供暖季前检查或办理入口变化应提前触发复核，不能只刷新核验日期。

## 仅用于虚构测试的年度阶梯模型

`scripts/life_modules.py` 提供 `fictional_annual_tier_charge`，必须显式传 `fictional=True`。函数不读取任何城市资料，主构建和网页不调用它，没有生产真实价格配置。此函数只是为后续经过审核的计算层打底，不能称为可用账单计算器。

在同一日历年、同一独立表、全年正常账期且单一非分时价格情况下，设此前累计用量为 A，本期用量为 U：

`本期费用 = F(A + U) - F(A)`，其中 F 对每一阶梯区间分别按用量乘单价求和。只对本期新增用量分段，不能将全量乘最高档，也不能将年限额按每月重置。返回分档用量、单价、未舍入金额；最终金额 Decimal 半入方式舍入到分。此舍入方式仅是测试约定，不声称是任何供应企业结算方式。

测试全部使用虚构阈值100、200和虚构单价1、2、3，绝不映射到试点城市。跨年输入拒绝，调用者须明确按年拆账并在新年度设累计为0；峰谷、多人户、合表、租金包费、未满年度账期以及非人民币都拒绝，不做近似。负数、非有限值、布尔值、超出测试范围、倒序阈值与缺失最终无上限档也拒绝。100万的输入上限是模型防护，不是政策限额。

验证命令：

```sh
python3 -m unittest discover -s tests -p test_life_modules.py -v
```

10个测试覆盖阈值前/等于/超过、年累计跨档、跨年拒绝和显式重置、小数舍入、零用量、异常数值、所有未支持场景、许可及生产启用阻断、日期窗口、尚未生效和过期状态。测试通过不意味着任何真实费率已获核准。

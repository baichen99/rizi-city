# 居民城市概况数据 v1

这是实施样板，不是全国数据库。核验日期为 2026-11-09。试点为北京、广州、上海。生活概况不参与日子指数，不改变旧租金、收入、消费和社保字段。缺失不等于零；可打开不等于可再分发。

## 当前交付和缺口

- 三城新建商品住宅**同比价格指数**：已有2026年6–9月基础记录，并按一城一PR向前补充2026年5月；各城实际覆盖期以系列记录为准。初版8月缺口已通过官方原文核对补齐；未来缺口仍保持断线，不插值。单位是“上年同月=100”，不是元/㎡，不是涨跌百分比，不反推绝对房价。2026起使用2025对比基期及新权数，此批只取该方法版本。
- 广州非私营、私营单位就业人员年度税前平均工资：2023–2025各年原文数值。不是“在岗职工”口径，也不是居民可支配收入或到手工资。2024原文明确法人单位就业人数5人及以上，而邻年页面未明确相同门槛。为避免误导，各年可查看，但2024分组断线，不能把未核实的方法一致性当成连续趋势。
- 上海年鉴工资与户籍人口期望寿命：原文表头、数据、脚注可读，但再分发条件未确认；只保留链接，源文件和构建产物均不保存数值。寿命年鉴参考范围1978–2022，工资年鉴参考范围2021–2024，**不是当前全量已发布历史**。
- 广州2025年居民预期寿命工作报告：原文已读；再分发条件与常住/户籍总体细节未完成确认，只给链接。
- 北京寿命历史：2020年82.43岁、2021年82.47岁，均为全市户籍居民男女合计的出生时时期寿命，2021公报直接回列比较2020。2022–2025仍为null，当前概况不回退到2021；没有跨城可比键。北京工资尚未取得合格原表。三城全市工资中位数均未取得已核验同口径来源，明确 `null` 和原因，不估算，不使用招聘报价或居民收入中位数替代。

寿命目前只发布北京2020–2021历史两点；上海、广州及北京较新年份仍有来源或口径缺口。用户可直接打开官方资料；不能为了画线而绕过来源资格或总体定义。

## 文件与集成 API

- `data/life/sources.json`：独立来源登记，包含原始URL、机构、原文发布日期（未知则null）、读取及核验日期、复核期限、人工读取方式、资料使用条款链接、限定的发布依据、署名、审查状态。
- `data/life/changelog.json`：首次记录从null到原文值的变化与具体依据；后续数值修订继续追加，不抹去旧记录。
- `data/life/series/<city_id>.json`：每城五个指标系列，记录时间、数值、单位、总体、地域、统计性质、来源、核验状态、缺失原因。保留每个数值在原文的位置 `evidence_locator`。
- `scripts/life_data.py`：`validate_life(data_dir=None) -> list[str]`；空列表表示通过。`build_life(city_ids, data_dir=None) -> dict[city_id, payload]`；验证失败抛出 `ValueError`，不会默默跳过坏记录。`validate_records(registry, cities)` 可用于单元测试。
- payload 包含 `schema_version`, `coverage`, `series`, `overview`, `sources`。每个 overview 精确复制对应系列**最后一个期间**的记录，包括该期缺失，不偷偷回退到旧值。不存在的城市明确 `not_covered`。
- 系列附 `coverage_start`, `coverage_end`, `verified_points`。点记录附便于前端署名的 `source_url`, `source_title`, `attribution`。这些附加字段仅在构建时产生，不另存事实副本。

日期与期间用字符串；金额保留原文年值，前端不默认除12。数据层真实数值是原文直接事实摘录，数据文件不保存派生估算；页面标注的量级示例见下文。每次构建不访问外网，输入固定则输出可复现（复核过期门禁除外）。

## 比较与折线

`comparability_key` 限定城内同一口径；人口、单位、统计方法、房价市场类型、指数基期等变化必须分段，`break_reason` 写明原因。不能只改一个键来伪装同口径。缺失月份必须显式null，禁止插值或跨缺口连线。前端还须验证实际期间连续及记录语义。

生活扩展层中，三城房价指数额外设置 `cross_city_comparability_key=nbs-new-yoy-2025-city-districts`，表示相同NBS调查方法、商品住宅分类和市辖区（不含县）地域类别；各城市真实地域名称仍保留。跨城比较还必须检查单位、时间、人口及审查状态一致。不同工资类型、户籍与常住人口寿命不可直接比较。没有跨城键不是错误，是没有可比性承诺。

## 校验与维护

`python -m unittest discover -s tests -p test_life_data.py -v` 覆盖null与0、NaN/无穷/布尔/负数、日期与期间、伪装gov.cn域名、未知来源、受限原始值、构建抑制、过期、缺口、单位/总体变化、显式口径分段和概况/历史同源。

所有页面核对是一次有限人工读取，不存在定时抓取任务、登录或授权API。新增/修订数据须重新打开原文、核对字段位置和条款，保留真实发布日期与核验日，不把重新核验当成新政策。历史修订保留原文依据并在PR写明变动，人工审查后才合并。

## 页面解释与量级示例

页面保留原始数值、单位、期间、统计对象和来源，不修改数据文件或评分公式。只有明确标注“上年同月=100”的已核实房价同比指数，才以指数减100解释同比涨跌百分比；编制方法基期与同比参照分别列出，不把同比走势当作环比，也不倒推每平方米售价。

年值默认仍按年展示。展开解释中的“年数÷12”和“租金单价×假设30㎡”只是标明假设的量级示例，不是新的月度统计、实际房源报价或个人到手收入。没有已核实值时不产生该示例。历史缺口仍留空，旧年值不冒充当期。

居民收入与消费只有通过[独立元数据契约](resident-statistics-metadata.md)核验后才开放跨城比较。页面验证原值、年份、真实日历日期、名义金额、人口与地域类型、调查方法及固定比较键；缺失、错误或过期时不升级。统计人口与初步数标签直接显示，不能把城镇常住居民均值当成全体居民、工资或个人预算。尚未确认的口径写“未确认一致”，不冒称已知不同。
